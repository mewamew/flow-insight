# Flow Insight · 心流洞察

通过屏幕内容、应用活跃记录和可选的本地在座检测，每 60 秒尝试调用 AI 分析工作状态，回看投入、中断与恢复，发现适合自己的工作节奏。摄像头图片不保存、不上传。

**macOS 14+ · Rust 后端 · Web 前端 · qwen3.8-flash**

## 启动

```bash
./scripts/start.sh
```

打开 <http://127.0.0.1:17901>。第一次使用，在“设置”中配置模型，再通过“开始观察”授权屏幕录制；任务描述可留空，留空按活动性质粗判，填写后按任务相关性判断；摄像头默认勾选，开始前可取消。网页关闭后后台继续运行，可从菜单栏暂停或退出。

```bash
# 导入自己的模型配置；脚本不会打印密钥
python3 scripts/import-qwen.py /path/to/qwen.txt
# 停止后台
./scripts/stop.sh
```

本项目使用 Rust 1.88.0（rust-toolchain.toml 固定）与 Xcode Command Line Tools。前端为原生 HTML/CSS/JavaScript，无 Node 构建步骤；AppKit/ScreenCaptureKit/AVFoundation 的平台适配只负责系统采集和原生卡片，业务与模型调用在 Rust。

## 功能

- **心流概览**：最近状态、工作画面、三路采集依据；保留交互时间线，增加按小时排列的工作节奏图，同一分钟内的状态变化与未记录空隙分别显示，点击可查看依据。
- **画面回放**：查看屏幕、前台应用变化与本地在座状态，分别筛选 AI 画面、本地观察和离席记录。
- **状态洞察**：保留当天的小时投入分布、中断与恢复对照、Qwen 发现与建议；增加近 7 / 14 / 21 天的高能时段热图，记录足够且时段差异明显时才显示相对集中的时段，可跳回当天记录。
- **固定分析**：开始时先尝试一次，此后每 60 秒尝试一次；应用或窗口变化不再触发额外分析。确认离席、锁屏或进入排除应用时暂停；模型忙或调用失败时等待下一轮。每次判断从截图起最多有效 2 分钟，过期显示未判断。
- **桌面轻提醒**：近期多次高置信度偏离采样、满足时间间隔及本地活动连续性后提醒；15 分钟冷却、主动暂缓、查看对应记录。
- **记录管理**：暂停、续开新会话、调整可选任务和每日目标、排除应用、导出与删除。

状态来自间隔采样与 AI 辅助判断，并不是精确测量心理学意义上的心流。观看视频和切换应用不直接等于走神；信息不足单独显示。

## 数据

数据保存在 `data/runtime/`，已从 Git 排除。该目录权限为 700，密钥和图片文件权限为 600。网页不会得到密钥。需要分析时，仅将屏幕采样、应用活动、本地在座结果及工作背景发送到配置的 AI 服务。摄像头画面只在内存中交给 Apple Vision 判断是否有人，不采集音频；首页取景窗的实时预览直接来自内存，只经本机地址显示，可随时隐藏，不保存、不上传。旧版已保存的摄像头图片不自动删除，也不会随重新分析上传。默认保留 7 天，到期数据在启动与后台维护时清理。

模型调用使用用户保存的 API 地址、Key 和模型，默认地址为 `https://dashscope.aliyuncs.com/compatible-mode/v1`。应用不按套餐类型拦截端点，包括已配置的 Token Plan；连接、认证、限流等问题按服务端实际响应提示。

## 开发与验证

```bash
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
node --check src/web/app.js
node --test tests/hero-state.cjs tests/rhythm.cjs
./scripts/build-macos.sh
```

测试和验证脚本必须使用独立的数据目录（通过 `FLOW_INSIGHT_DATA_DIR` 指定），不要读写 `data/runtime/` 中的真实记录。
